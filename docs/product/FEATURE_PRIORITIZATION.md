# Priorización de funcionalidades

Ordenado por valor de la demo, evidencia científica y dependencia. P0 bloquea entrega; P1 completa el MVP; P2/P3 se revisa después. Estado real del bootstrap en [informe](../BOOTSTRAP_REPORT.md).

| Prioridad | Funcionalidad | Motivo / aceptación |
| --- | --- | --- |
| P0 | Base ejecutable, contratos, CI y privacidad | Permite trabajo paralelo y reproducción sin secretos. |
| P0 | Ocho taxones y fotos permitidas | IA/evaluación necesitan referencia y derechos. |
| P0 | Uso real Meta y abstención | La entrega requiere evidencia del modelo, no solo mock. |
| P0 | Evaluación y demo verificables | No publicar precisión ni claims sin protocolo/resultados. |
| P0 | Elegibilidad, representante, derechos y envío | Un producto útil puede quedar fuera si incumple reglas. |
| P1 | UI accesible móvil, fichas y captura | Recorrido completo y comprensible con carga/error/vacío. |
| P1 | Atlas y observaciones trazables | Conecta individuo y territorio, persistencia validada. |
| P1 | Una ventana CHMv2 | Explica estructura del bosque con fuente e incertidumbre. |
| P2 | Más taxones, fotografías y rutas verificadas | Ampliar tras validar experiencia y licencias. |
| P3 | DINOv3, crecimiento, invasoras e infraestructura | Investigación posterior; requiere nuevos datos, permisos y evaluación. |

No añadir cuentas complejas, gamificación, red social, pagos, app nativa u offline durante el bootstrap. Antes de exposición pública sí se requieren controles de acceso/retención adecuados; no posponerlos para publicar datos reales.
